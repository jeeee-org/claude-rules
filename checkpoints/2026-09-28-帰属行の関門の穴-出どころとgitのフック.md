# 2026-09-28 帰属行の関門の穴 — 出どころの設定とgitのフック

## 依頼

別PCの改善メモ（`IMPROVEMENTS.md` 2026-09-28「AI帰属行の関門を、commitとpushを同じ呼び出しで行う形がすり抜ける」）。業務のテストPJ（自動pushのPJ）で、`Co-Authored-By: Claude ...`付きのcommitが共有ブランチへ繰り返し押されていた（全2038件中46件）。`push-attribution-guard.sh`はPreToolUseで「押し出す未pushのcommit」を読むので、commitとpushを同じ呼び出しで打つとcommitがまだ無く0件に見えて通る。スクリプトの中のpushはコマンドに現れない。

貼り付けられたメモは数か所が欠けていた（原因②の途中・改善案1・2の途中）。文脈から補って収録し、その旨を本文に残した。

## やったこと

1. **出どころ**：`settings/attribution.json`を新設（`{"attribution": {"commit": "", "pr": "", "sessionUrl": false}}`）。`install.sh`の`apply_attribution_settings`が`~/.claude/settings.json`に`attribution`キーが無い時だけ足す。あれば上書きせず、帰属行を出す値（`false`でも空文字2つでもない）なら警告。opt-outは`--no-attribution-settings` / `CLAUDE_RULES_ATTRIBUTION_SETTINGS=0`。
   - 公式settings-reference「Git and attribution」で確認：`attribution: false`はv2.1.281以降のみで、古い版は設定ファイルごと読み飛ばす。どの版でも読める空文字の形を選んだ。`includeCoAuthoredBy`はv2.0.62で非推奨。
   - このPCで`./install.sh`した直後、セッションへの帰属の指示が「末尾に付けよ」から「付けるな」に替わった（設定が即時に効き、モデルへの指示も消えることの実測）。
2. **gitのフック**：`hooks/git-commit-msg.sh`（マーカー`claude-rules:commit-msg`）。commitメッセージから帰属行（関門と同じ正規表現、大文字小文字無視）を取り除き、末尾の空行も落とし、消した行をstderrへ。拒否にしなかったのは、PJの進捗コミット用スクリプトやループの工程を途中で落とさないため。`CR_SKIP_ATTRIBUTION_GUARD=1`で抜ける。同じ場所の`commit-msg.local`があれば続けて`exec`する。
   - 置くのは`tools/embed-rules.py`。`git rev-parse --git-common-dir`の`hooks/`（worktreeでも共有）。前からある他のcommit-msgは`commit-msg.local`へ退避（`.local`も既にあれば置かずに知らせる）。`core.hooksPath`が設定されたリポは置かずに知らせる（husky等の管理下へ書くとリポに入ってしまう）。
   - `--scan`に「commit-msgフックなし／古い」、`--check`はフックが無ければexit 1、`--remove`で外して`.local`を戻す。`.git/hooks`はcloneに付いてこないので、版が最新でも`embed-rules.py <PJ>`で置き直せる形にした。
3. **関門の補助**：`push-attribution-guard.sh`に、同じ呼び出しに`git commit`とpushがある時だけ、コマンド全体（ヒアドキュメントの本体を含む）を小文字化して署名の形を探し、見えれば止める判定を足した。未pushのcommitを読む既存の判定より前に置いた。
4. **見送り**：改善案4（PJ固有の節に業務/個人の欄）。1で指示そのものが出ず、2で行も消えるので、推し量る場面が残らない。
