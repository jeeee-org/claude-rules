# 2026-09-18 関門の2つの空振りを塞ぐ

他PCと自分のセッション、2台の実測報告（`IMPROVEMENTS.md`の同日の項目に集約）。**導入初日のcommitは、ほとんど検査されていなかった。** 失ったデータは無いが、関門があるつもりで進んでいた。

## 原因は独立した2つだった

指摘のとおり、片方だけ直してももう片方が残る。順番も指摘どおり、切り出し → 変更なしの扱い。

**① 検出の空振り。** `head_part=${cmd%%<<*}`が最初の`<<`以降を全部落とすので、`cat >> f <<'EOF' … EOF` のあとに`git commit`を書く形だと、**commitの検出そのものに入らなかった**。この形は私の常用で、今日のcommitの大半がこれ。同じ`head_part`を印の判定にも使っていたので、**疎通確認の印を後ろに書くと確認も空振りする**。
→ `<<`で切るのをやめ、**ヒアドキュメントの本体（デリミタからデリミタまで）だけを落とす**awkに替えた。ヒアストリング（`<<<`）は対象外。

**② 判定の空振り。** `PreToolUse`はコマンドの実行**前**なので、`printf … > f && git add … && git commit`を1呼び出しで打つと、**書き込みもaddもまだ起きておらず「変更なし」で通る**。
→ **書き込みの気配とcommitが同じ呼び出しにあるなら、判定せずに「分けて打つ」ことを求める**（exit 2）。`git add`だけは書き込みではないので対象外——対象の変更は既にディスクにあり、判定できる。

## 後追いの網を足した

`hooks/commit-record-audit.sh`（`PostToolUse`）。**できてしまったcommitを後から見る。** 直前の呼び出しでcommitができていたら`git show --name-only HEAD`を見て、記録が無ければ知らせる。**止められない**が、**コマンドの書き方によらずgitの履歴そのものを見る**ので見逃しが残らない。直近120秒以内のcommitだけを対象にし、記録の方式を使っていないリポでは黙る。

入口（止められるが形に弱い）と後追い（止められないが形に強い）の二段構えにした。

## 案内として足したもの

- **差し戻しの文面に「このコマンドは1行も実行されていません」を必ず入れた。** 「commitだけ止まった」と読むと、同じ呼び出しでしていた`git add`も走っておらず、次のcommitが`no changes`で空振りする（実際に起きた）。
- **疎通確認は単独の呼び出しで打つ**ことを、`check-record-guard.sh`の②の注意に入れた。前に別のコマンドを繋げると素通りし、「効いていない」と誤って読む。
- **`install.sh`が`settings.json`を書き換えることを、書き換える前に告げる**ようにした。あわせて`--no-hook-register`（`CLAUDE_RULES_REGISTER_HOOKS=0`）を用意し、冒頭の説明と`--help`にも載せた。**これは私の手落ち**で、設定ファイルの変更は最初に伝えるべきだった。相手のセッションはこれを理由にinstallを保留し、利用者の判断へ回していた。

## 誤った説明を直した

「セッション単位で割れる」「リポ単位で割れる」と2度書いたが、**どちらも違った**。実際は**1回の呼び出しに何を詰めたか**で決まる。フックの見出し・確認コマンド・README・`install.sh`の案内・`NOTES.md`を、すべてこの説明に直した。

## この作業中に、報告の3番をそのまま踏んだ

前の作業（疎通確認）で、カードを畳む・`PROGRESS.md`を直す処理を**commitと同じ呼び出しに入れていた**。その呼び出しが関門に止められ、打ち直した時に**記録の書き込みだけを再実行して、カードの片付けを落とした**。結果、終わったはずのカードが「進行中の作業」に残り、`PROGRESS.md`の1行も古い（誤った）説明のまま入っていた。この作業で拾って直した。
