# 2026-09-18 commit時の記録の関門

記録（`REQUIREMENTS.md` / `PROGRESS.md` / checkpoint）がルールどおりに更新されないことがある、という指摘から。リマインドではなく機械の関門にした。

## 何を作ったか

**`hooks/commit-record-guard.sh`** — `PreToolUse`（Bash）フック。commitしようとした時に、記録の4点（`REQUIREMENTS.md` / `PROGRESS.md` / `NOTES.md` / `checkpoints/`）のどれかが一緒に変わっているかを見て、1つも無ければ**commitを止めて差し戻す**。

- **止める強さ**：exit 2 でメッセージを私へ返す。警告だけだと素通りするため。
- **通す口**：`CR_SKIP_RECORD_GUARD=1`をコマンドの先頭に付ける。記録の要らない小さなcommitは実在するので、禁止ではなく「意識した判断の強制」にした。通した事実がコマンドに残るので、後から見て抜けと区別できる。
- **黙って通す条件**（fail-open）：`--amend`・`--dry-run`、gitの外、記録の方式を使っていないPJ、変更が無い、`jq`も`python3`も無い。
- **`CLAUDE.md`は数えない**。ルールだけを直したcommitにも記録は要る。
- commitの形の判定は`git [-C path|-c k=v]... commit`だけを拾い、**ヒアドキュメントの中身は見ない**（commitメッセージ本文に「git commit」や「PROGRESS.md」と書いてあっても判定に混ぜない）。
- `cd X && git commit`の形では行き先のリポで見る。**`eval`は使わない**（コマンド文字列をそのまま展開すると、そこが実行口になる）。

**`tools/tests/test_commit_record_guard.py`** — 15件。止まる側（記録なし・add連結・メッセージ本文だけ記録に触れている・cdで別リポ）と、通る側（checkpoint追加・日本語のパス・PROGRESS更新・モノレポ配下・通す指定・amend/dry-run・commitでないコマンド・Bash以外・gitの外・記録の方式を使っていないリポ・変更なし）。全体で37件が通る。

**`install.sh`** — フックの配置に加え、**`~/.claude/settings.json`への登録まで行う**（トリアージ分類と違い既定で有効）。登録前に控え（`settings.json.bak`）を取り、同じコマンドが既にあれば足さない（再実行で二重に増えない）。`jq`が無い時とJSONとして読めない時は、何もせず手順を知らせる。

## ハマった点

`git status --porcelain`が**未追跡のディレクトリを`dir/`の1行に畳む**ため、モノレポのテスト（`tasks/a/checkpoints/…`を新規作成）だけが落ちた。`-uall`で1ファイルずつ出して解決。`NOTES.md`へ。

## 確かめたこと

使い捨てのリポで、記録なしのcommitが止まること・checkpointを足すと通ることを実測。`install.sh`の再実行で`PreToolUse`が1件のままであることも確認した。

## 残り

Codex側には同じ口が無い（`codex-triage`は起動ラッパーで、ツール実行前のフックではない）。Codexをメインに使うPJでは関門が効かない。
