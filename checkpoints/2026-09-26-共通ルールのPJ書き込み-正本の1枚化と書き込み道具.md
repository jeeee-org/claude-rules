# 2026-09-26 共通ルールのPJ書き込み — 正本の1枚化と書き込み道具

## 依頼
グローバルルールを使わずに他の人へルールを配る時のため、共通ルールを個別PJのルールファイルへ重ねて書き込む版をオプションで作る。グローバルを入れる人は従来どおり。Codexを使う人と、このリポを入れられない人へは、PJへ共通ルールごと入れて配る。文面は「両方から読める1枚を先に作る」（提案したおすすめ）で進めると決まった。

## やったこと

### 1. 共通ルールの正本を1枚にした
- `rules/common-rules.md`を新設。Claude版を土台に、読み手で違う語は`{{PJ}}`・`{{CHECK_LIMITS}}`・`{{INIT}}`・`{{SKILL_PATH}}`・`{{LIMIT_COMMON}}`・`{{LIMIT_PJ}}`・`{{START_SCOPE}}`、片方だけの文は`<!-- if:条件 -->…<!-- endif -->`（行単位でも行の途中でも）で書く。
- `tools/build-rules.py`で5つの版を作る：`claude-global` / `codex-global` / `embed-claude` / `embed-codex` / `embed-both`。`rules/global-rules.md`と`rules/codex-global-rules.md`は生成物になった（commitはしておく。他PCのinstallと差分の読みやすさのため）。
- `install.sh`は配る前に`build-rules.py`を呼ぶ（揃っていれば何も書かない。python3が無ければコミット済みの生成物をそのまま配る）。

### 2. 各版の中身の変化
- **Claude版**：意味の変化は2か所だけ。§5.2の禁止②を「Claude / AI系」→「AI系（Claude / Codex / OpenAI等）」、§7にPJ側へ書く物の例示を追加。ほかは表記（`PJのCLAUDE.md`にコード印）とマーカー行の正本名。12,472 → 12,694B（残り1,642B）。
- **Codex版**：Claude版の文体へ全面的に揃った。消えた物＝§2の「開始時はAGENTS.mdとPROGRESS.mdを読む」（§1・§3と重複）、§4の記録先の対応表（§1の表と重複）、§6の「項目の頭に取得日を書く」（`codex-init-rules`の雛形側にある）、§9の「防ぐのは記録ではなく毎回の1行」。増えた物＝§3のスキルの置き場（`.agents/skills/`）、§5の`GH007`の対処・§5.1の配置の決まり、§5.2のPR方針。11,361 → 12,482B。
- **PJ書き込み版**：相手のホームにある物を指さない。記録の関門・AI帰属行の関門・`init-rules`への言及を外し、上限の判定は`.claude-rules/check-limits.sh`を指す。`both`は冒頭に「Claudeは`CLAUDE.md`の`@AGENTS.md`から読む」を1行足す。約12.5〜12.7KB。

### 3. PJへ書き込む道具
- `tools/embed-rules.py <PJ> [--target both|claude|codex] [--dry-run|--check|--remove]`。
- `both`：`AGENTS.md`の先頭にブロック、`CLAUDE.md`の先頭に`@AGENTS.md`（無ければ作る）。PJに`CLAUDE.md`があるとClaude Codeは`AGENTS.md`を読まないので、読み込みで繋ぐ。
- マーカー行に版（`rules/common-rules.md`の最終commit、未commitなら`+dirty`）と種類を刻む。2回目以降はマーカー間だけ差し替える。`--check`は版の刻みだけの違いを最新とみなす。
- `<PJ>/.claude-rules/check-limits.sh`を一緒に置く。
- 知らせる物：このPCのグローバルにも共通ルールがある（二重に読まれる）／`both`で`CLAUDE.md`にPJ固有の指示が残っている（Codexに届かない）／別の`--target`で書いたブロックの残り。
- commitはしない。

### 4. 上限の判定
- `tools/check-limits.sh`：PJの`CLAUDE.md` / `AGENTS.md`に書き込みブロックがあれば、マーカー間をグローバルの上限（14,336B）、外をPJの上限（6,144B）で分けて測る。グローバルにも共通ルールがあれば△で二重読み込みを知らせる（失敗にはしない）。

### 5. テスト
- `tools/tests/test_build_rules.py`：条件の書き方、仕掛けの残り、版ごとの指す先、上限、コミット済みの生成物が正本と揃っているか。
- `tools/tests/test_embed_rules.py`：`both` / `claude` / `codex`の書き込み先、PJ固有の指示の保持、2回目の変更なし、古いブロックの差し替え、既存の`CLAUDE.md`への読み込み追加と警告、`--dry-run`、二重読み込みの警告、`--remove`で元に戻ること、上限の分割測定。
- 全225件が通過。

### 6. 周辺
- README（構成表・「PJへ共通ルールを書き込む」節・「ルールを変更するとき」）、PJの`CLAUDE.md`（正本の所在）、`skills/init-rules/SKILL.md`（編集しない正本の名前）、`tools/collect-state.sh`（採取対象に正本を追加）。
- `./install.sh`でローカルに反映済み。
