# 2026-09-20 `.claude`と`.codex`の統一の見通し（調査のみ・着手なし）

## きっかけ
「ClaudeがAGENTS.mdで使えるようになったそうですね」という問いから、共通ルールと
`init-rules`を2枚ずつ保守している現状を見直せるかを調べた。**着手はしない**方針を
途中でユーザーが明示（「今やりませんよ？　将来的な話を聞いてるだけです」）。

## 確かめたこと

### 1. Claude CodeのAGENTS.md対応（公式ドキュメント）
- v2.1.277で着地。手元は2.1.278。
- 既定は`claude-md-or-agents-md`。**作業dirとその祖先に`CLAUDE.md` / `.claude/CLAUDE.md` /
  `CLAUDE.local.md`が1つでもあると、AGENTS.mdは読まれない。**
- `~/.claude/CLAUDE.md`・組織のmanaged・`.claude/rules/`はこの抑止判定に**数えられず**、
  AGENTS.mdと並んでロードされる。
- 設定値は`claude-md` / `claude-md-or-agents-md` / `claude-md-and-agents-md` / `managed-only`。
  置き場は`~/.claude/settings.json`の`pluginConfigs`→`agents-md@builtin`、`--settings`、
  managed settingsのみ。**project/local settingsでは効かない。**
- AGENTS.mdは`/memory`・`/context`に**出ない**（importした場合だけ出る）。Bedrock経由や
  テレメトリ無効のセッションでは読めない。
- `@path` importはAGENTS.md内でも展開される。

### 2. 実測（scratchに親子ディレクトリを作って`claude -p --model haiku`）
`oya/AGENTS.md`（KITSUNE）、`oya/.claude/AGENTS.md`（TANUKI）、`oya/CLAUDE.md`（INU）を
置き、`oya/ko`から秘密語を答えさせた。

| 条件 | 返った語 |
|---|---|
| CLAUDE.mdなし | `KITSUNE-1234, TANUKI-7788` |
| CLAUDE.mdあり・既定 | `INU-5555`のみ |
| CLAUDE.mdあり・`claude-md-and-agents-md` | `INU-5555, KITSUNE-1234, TANUKI-7788` |

→ 祖先の`<dir>/AGENTS.md`と`<dir>/.claude/AGENTS.md`は**両方**読まれる。抑止は**全部落とす**
形（部分的に残らない）。ドキュメントの記述どおりだが、`~/.claude/AGENTS.md`が祖先探索で
拾われる点は明記が無く、実測で確認した。

### 3. 各層の到達点（調査の核心）
- **PJ層のルール** = 解決済み（v2.1.277）。
- **グローバル層のルール** = 未解決。`~/.codex/AGENTS.md`は`~/.claude`と並ぶ兄弟で、
  Claudeの祖先探索の外。agents.md本体のissue #91が共通の置き場`~/.config/agents/AGENTS.md`
  （XDG準拠、Windowsは`%APPDATA%\agents\`）を提案中だが**提案段階**。現状はCodex
  `~/.codex/`、droid `~/.factory/`、Amp `~/.config/`とばらばら。
- **skills** = フォーマットは**決着済み**。Agent Skills Open Standardが2025-12にagentskills.io
  で公開、48時間以内にOpenAIとMicrosoftが対応、2026-05時点で32以上のツールが実装、
  ガバナンスはLinux Foundation傘下のAAIF。残るのは置き場だけ。
- **Codexの非対称** = AGENTS.md探索が**git rootで止まる**（openai/codex issue #15683）。
  共通の親ディレクトリに1枚置く形はClaudeでは成立し、Codexでは成立しない。

### 4. #6235が通った理由（予測の立て方の訂正）
2025-08-21起票 → 2026-09-18着地で約13か月。issueの核は「Codex、Amp、Cursorがagents.mdに
収束しつつある。CLAUDE.mdはClaude Codeに固有すぎる」。**Anthropicの利害ではなく、
指させる外部標準があったこと**が効いた。当初「Anthropicに動機が無いので薄い」と見立てたが、
予測に使うべきは「準拠先が立ち上がっているか」だった。ユーザーの指摘で訂正。

### 5. 2枚のずれの正体
- `rules/global-rules.md`（12,226B）と`rules/codex-global-rules.md`（11,277B）= 差分218行。
  §1〜§9の骨格は**完全に同じ**で、文体だけが違う（太字の箇条書き対散文、表の列名が
  「いつ読む／いつ書く」対「読む時／書く時」）。
- `skills/init-rules/SKILL.md`（11,601B）と`skills/codex-init-rules/SKILL.md`（3,692B）=
  差分203行。**対立ではなく、片側にしか無い雛形**。Claude版は生成する雛形の本文
  （約120行）を埋め込み、Codex版は同じ手順を散文で説明して雛形を持たない。手順・4文書・
  カードの形・改善案の記録節は同じことを言っている。
- 突き合わせ相手が無いもの: `migrate-rules`（Claude専用・18,637B）、`codex-triage`
  （Codex専用・1,374B）。`quorum`は別リポ。

## 未確認のまま残したこと
