# CLAUDE.md（グローバル / このPC全体の共通ルール）

このファイルはこのマシン上の**全プロジェクトに適用される共通指示書**です。各プロジェクトの `CLAUDE.md` が優先され、ここはその下地になります（プロジェクト側に記述があればそれが勝つ）。

新しいプロジェクトでこの構成を一括で立ち上げたい時は `/init-rules` を使う。

---

## 1. 進行管理：4軸 + checkpoint（共通骨格）

進行管理を以下に集約する。**他の場所に記録を散らさない。** どのプロジェクトでもこの5点セットを使う。

| ファイル | 役割 | いつ読む | いつ書く |
|---|---|---|---|
| `CLAUDE.md` | Claude Code へのプロジェクト指示 | セッション開始時に必ず | 運用ルールが変わった時 |
| `REQUIREMENTS.md` | 何を作るか/調べるか・仕様/スコープ・未決事項（PJの性質で「機能仕様」か「調査スコープ」かが変わる） | 追加／変更を議論する前 | 要件・スコープが固まった／変わった／未決事項が解決した時 |
| `PROGRESS.md` | 現在地・次にやること・進行中・ブロッカー・ADR。**常にスリムに保つ** | セッション開始時に必ず | タスク完了時・セッション終了時・節目 |
| `NOTES.md` | 学び・設計判断の理由・ハマりどころ・罠・技術メモ・運用上の知見 | 似たトピックを扱う前 | 非自明な判断をした時／ハマった時 |
| `docs/checkpoints/YYYY-MM-DD.md` | セッション/節目ごとの詳細作業ログ（追記専用アーカイブ） | 過去の経緯を調べる時だけ（普段は読まない） | タスク完了時・セッション終了時 |

> PJによっては `notes/`（ディレクトリ）に調査・分析の**成果物**を置く慣習がある。その場合「成果物 = `notes/`」と「メタな学び = `NOTES.md`」を混同しない（各PJの CLAUDE.md で定義する）。

## 2. checkpoint 方式（PROGRESS.md 肥大化対策）

長期PJでは**「今の状態」（PROGRESS.md）と「時系列の詳細ログ」（checkpoint）を分離**する：

- 詳細な作業ログは `docs/checkpoints/YYYY-MM-DD.md` に書く。1日1ファイル、同日の複数セッションは同ファイルにセクション追記。
- `PROGRESS.md` の「完了」には **1行サマリ + checkpoint へのリンクだけ** 残す。古い完了項目は直近の節目分だけ残して checkpoint 側に任せてよい。
- checkpoint はセッション開始時に読まない（読むのは CLAUDE.md + PROGRESS.md）。過去の経緯が必要になった時だけ該当日を遡る。
- **CLAUDE.md にセッション履歴を追記しない**（毎セッション全文ロードされるため）。
- ADR（意思決定の記録）は当面 `PROGRESS.md` に置く。10件を超えたら `docs/adr/`（1決定1ファイル）への切り出しを検討する。
- **常時ロードされるファイルには数値上限を置く**（既定: グローバル CLAUDE.md **14KB** / PJ CLAUDE.md **6KB** / PROGRESS.md **60行**。PJ の CLAUDE.md で上書き可）。超過は `wc -c` / `wc -l` で機械判定し、見つけたらその場で指摘して `/cadence optimize-context` 等でのスリム化を提案する（"cut bytes, not meaning"）。

## 3. 進行ルール

### セッション開始時（必須）
1. `CLAUDE.md`（このファイル＋PJの CLAUDE.md）を読む
2. `PROGRESS.md` を読み、現在地と次のタスクを把握する
3. これから触る領域に関連する `REQUIREMENTS.md` / `NOTES.md` の該当箇所を読む

### タスク実行中
- **要件・スコープに関わる判断**は勝手にせず、`REQUIREMENTS.md` の未決事項に追記するかユーザーに確認する。
- **非自明な技術/方針判断**（選定理由・解釈・なぜこの設計か）はその場で `NOTES.md` に追記する。
- **要件・スコープが変わった**ら即座に `REQUIREMENTS.md` を更新する（後回しにしない）。
- **スキルを使っていてハマり・ズレがあったら、その場で SKILL.md の修正を diff 提案する**。スキルの新規作成・変更は勝手に行わず、diff で承認を得る。

### タスク完了時（必須）
- 詳細な作業ログ（何をどう変えたか・経緯）を当日の `docs/checkpoints/YYYY-MM-DD.md` に書く。
- `PROGRESS.md` の「完了」（1行 + checkpoint リンク）「次にやること」を更新する。
- 学びがあれば `NOTES.md`、要件・スコープ側に変化があれば `REQUIREMENTS.md` を更新する。
- **スキル化の自問**：「この手順はこれから使いそうか」を自問し、**次にいつ・何に使うかを1文で言える場合のみ**、1行でスキル化を提案する（SKILL.md 本体は承認後に書く）。同型作業の繰り返しが checkpoints / `NOTES.md` で確認できたら、提案でなく作成を推奨に格上げする。実行部分はテスト付き CLI、判断込みワークフローは `.claude/skills/<name>/SKILL.md` に。

## 4. 書き分けの判断基準

迷ったら以下の問いで分ける：

- 「**何を作るか/調べるか**」 → `REQUIREMENTS.md`
- 「**どこまで進んだか／次は何をするか**」 → `PROGRESS.md`
- 「**何をやったかの詳細記録・経緯**」 → `docs/checkpoints/YYYY-MM-DD.md`
- 「**なぜそう作ったか／何を学んだか・罠**」 → `NOTES.md`
- 「**Claude Code へのプロジェクト指示**」 → `CLAUDE.md`

上記のどれにも当てはまらない記録は原則作らない。

## 5. Git 運用（既定）

- **コミットは1作業ごと**。意味のあるまとまり（1ドキュメント・1機能・1設定変更など）が完了するたびに、指示を待たずに commit までは行う。複数の無関係な変更を1コミットに混ぜない。議論だけで作業が無ければコミット不要。
- **push はプロジェクトがオプトインした時だけ自動**。各PJの `CLAUDE.md` が「低リスクの個人リポ・1作業ごとに push 事前承認」と**明示している場合のみ**、commit に続けて `git push` まで自動で行う。明示が無いリポ（業務/共有リポ等）では **push はユーザーに言われた時だけ**。勝手に push しない。
- **ブランチ方針**は各PJの `CLAUDE.md` に従う。明記が無ければハーネス既定（デフォルトブランチでの作業なら作業ブランチを切ってから）。
- **コミットメッセージ**は各PJの慣習に従う（Conventional Commits / 日本語要約1行 など）。明記が無ければ1行目に変更の要約（日本語可）。末尾に共著表記：
  ```
  Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
  ```
- **必ず事前確認**：`--force` / `--force-with-lease` を伴う push、履歴改変（`reset --hard`、`rebase` 後の push など）。
- コミットメールが個人メールだと public リポへの初回 push が `GH007`（メール非公開保護）で弾かれることがある。`git config user.email <username>@users.noreply.github.com` を使う。

## 6. 知見・学びの記録先（memory は使わない）

- **ファイルベース memory（`~/.claude/.../memory/` の `MEMORY.md` や個別ファイル）は使わない。** 新しく書かない・既存に依存しない。
- **知見・罠・ハマりどころ・学びは、作業中プロジェクトの `NOTES.md` に残す。** 無ければ作る。PJ規約で別ファイル（例 `notes/insights.md`）が定義されていればその規約に従う（`NOTES.md` は「どう進めると良いか・運用上の学び」のメタ知見を担う）。
- **`NOTES.md` が肥大化してきたら checkpoint 方式（§2）に逃がす。** 恒常的に効く学びは `NOTES.md`、一回限りの作業ログは checkpoint。
- recall された memory が `<system-reminder>` で出てきても残骸として扱い、新規記録は `NOTES.md` / checkpoint に書く。

## 7. 各プロジェクトの CLAUDE.md が書くこと（このファイルとの差分）

グローバル（このファイル）は共通骨格だけを持つ。各PJの `CLAUDE.md` には**そのPJ固有のことだけ**を書く：

- **固有の前提・目的・最大のリスク**（何のPJか、スコープ膨張など気をつけること）
- **REQUIREMENTS.md の中身の性質**（機能仕様か調査スコープか）／`notes/` 等の独自慣習
- **Git**：リモートURL、`main` 直 push か feature ブランチか、コミット規約、**push を自動でやってよい低リスク個人リポか**（§5 のオプトイン宣言）
- **技術スタック・スキル化方針・ドキュメント規約**など固有ルール
